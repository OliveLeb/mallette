# Use a transactional outbox for email

Security-related email is recorded in a PostgreSQL-backed outbox in the same transaction as the state change that requires it, then delivered asynchronously with bounded retries and administrator-visible failures. A dedicated Ace worker process claims messages with database locking so multiple workers cannot double-send; a missing or stalled worker degrades health without stopping the HTTP API. The API reports success once delivery is durably scheduled rather than waiting for SMTP. This adds a separately supervised process but prevents transient SMTP failures from leaving state changes without their corresponding message; when email delivery cannot be scheduled at all, email-dependent operations fail without changing state while the rest of the instance remains available.
